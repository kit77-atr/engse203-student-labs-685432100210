# บันทึกการไล่ปัญหา (Debug Log)

## BUG #0 · ตรวจสอบความยาว details ที่ค่าขอบ

- **อาการ:** รายละเอียด 10 ตัวอักษรพอดีต้องผ่าน แต่รายละเอียด 9 ตัวอักษรต้องไม่ผ่าน
- **วิธีทำซ้ำ:** เขียน unit test ส่ง `details` ความยาว 9 และ 10 ตัวอักษร
- **เครื่องมือ:** Vitest และ `api/tests/unit/requestValidator.test.js`
- **สาเหตุ (ไฟล์:บรรทัด):** `api/src/validators/requestValidator.js:37` — เงื่อนไขตรวจสอบความยาวต้องปฏิเสธเฉพาะค่าที่น้อยกว่า `MIN_DETAILS` ซึ่งกำหนดเป็น 10
- **วิธีแก้:** ตรวจสอบและปรับเงื่อนไขให้ใช้ `< MIN_DETAILS` โดยไม่ปฏิเสธค่าที่เท่ากับ 10
- **test ที่กัน:** Unit test รายละเอียด 10 ตัวอักษรต้องผ่าน และ 9 ตัวอักษรต้องถูกปฏิเสธ

## BUG #1 · ลบคำร้องแล้วเพิ่มใหม่ ได้ 500

- **อาการ:** เมื่อลบคำร้องแล้วสร้างรายการใหม่ อาจเกิด HTTP 500 เพราะรหัสคำร้องซ้ำ
- **วิธีทำซ้ำ:** ลบ `REQ-002` แล้วส่ง `POST /api/requests` ด้วยข้อมูลที่ถูกต้อง
- **เครื่องมือ:** Vitest, Supertest และ Checker ของ CP47
- **สาเหตุ (ไฟล์:บรรทัด):** `api/src/services/requestService.js:99-106` — การใช้จำนวนรายการเพื่อสร้างรหัสใหม่อาจสร้างรหัสที่มีอยู่แล้วหลังลบรายการ
- **วิธีแก้:** ใช้ `MAX(CAST(SUBSTR(id, 5) AS INTEGER))` เพื่อหารหัสตัวเลขสูงสุด แล้วสร้างรหัสถัดไป
- **test ที่กัน:** Regression test ลบ `REQ-002` แล้วสร้างคำร้องใหม่ ต้องได้ HTTP 201

## BUG #2 · Dashboard แสดง "กำลังดำเนินการ 0"

- **อาการ:** Dashboard แสดงจำนวนคำร้องกำลังดำเนินการเป็น 0 ทั้งที่มีคำร้องสถานะดังกล่าว
- **วิธีทำซ้ำ:** ส่งรายการที่มี `status: 'in-progress'` ให้ฟังก์ชัน `summarizeRequests`
- **เครื่องมือ:** Vitest และ `frontend/src/utils/requestSummary.test.js`
- **สาเหตุ (ไฟล์:บรรทัด):** `frontend/src/utils/requestSummary.js:14` — ค่าที่ใช้กรองสถานะไม่ตรงกับค่า `in-progress` ที่ API ส่งมา
- **วิธีแก้:** เปลี่ยนค่าที่ใช้กรองเป็น `in-progress`
- **test ที่กัน:** ทดสอบรายการ 4 รายการ โดยมีสถานะ `in-progress` จำนวน 2 รายการ และตรวจว่า `inProgress` เท่ากับ 2

## BUG #3 · เปลี่ยนสถานะคำร้องที่ไม่มีอยู่ ได้ 500

- **อาการ:** ส่งคำขอเปลี่ยนสถานะคำร้องที่ไม่มีอยู่แล้วได้ HTTP 500 แทน 404
- **วิธีทำซ้ำ:** ส่ง `PUT /api/requests/REQ-999` พร้อม `{"status":"completed"}`
- **เครื่องมือ:** Vitest, Supertest และ Checker ของ CP47
- **สาเหตุ (ไฟล์:บรรทัด):** `api/src/controllers/requestController.js:33-42` — มีการเข้าถึง `updated.id` ก่อนตรวจสอบว่า `updated` มีค่าหรือไม่ ทำให้เกิด TypeError เมื่อไม่พบคำร้อง
- **วิธีแก้:** ตรวจสอบ `updated` ก่อน หากไม่มีให้ตอบ HTTP 404 แล้วจึงบันทึก log และตอบ HTTP 200 เมื่อพบคำร้อง
- **test ที่กัน:** Regression test PUT ไปยัง `REQ-999` แล้วตรวจว่าได้ HTTP 404 พร้อมข้อความ error
